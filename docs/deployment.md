# Free deployment (for testing)

This deploys VendorOS across four free-tier services: a managed Postgres, a
managed Redis, the API, and the static frontend. None of these require a
paid plan for testing purposes.

| Piece                 | Service                        | Why                                                 |
| --------------------- | ------------------------------ | --------------------------------------------------- |
| Postgres              | [Neon](https://neon.tech)      | Permanent free tier, serverless, no card required   |
| Redis                 | [Upstash](https://upstash.com) | Permanent free tier, serverless                     |
| API (`apps/api`)      | [Render](https://render.com)   | Free web service, builds from `apps/api/Dockerfile` |
| Frontend (`apps/web`) | [Vercel](https://vercel.com)   | Free static hosting, builds from `vercel.json`      |

The repo already has the config files these services read: `render.yaml`,
`apps/api/Dockerfile`, and `vercel.json`. You only need to create accounts
and wire up environment variables — no code changes required.

## 1. Postgres (Neon)

1. Create a free account at neon.tech and a new project.
2. Copy the connection string it gives you (starts with `postgresql://`).
   Make sure it includes `?sslmode=require` (Neon adds this by default).
3. Keep this string — it becomes `DATABASE_URL` in step 3.

## 2. Redis (Upstash)

1. Create a free account at upstash.com and a new Redis database (choose a
   region close to wherever you deploy the API).
2. Copy the "Redis Connect URL" (`rediss://...`) from the database details
   page.
3. Keep this string — it becomes `REDIS_URL` in step 3.

## 3. API (Render)

1. Push this repo to GitHub (already done if you're reading this from the
   PR branch).
2. In Render, choose **New > Blueprint** and point it at this repo. Render
   reads `render.yaml` and creates the `vendoros-api` web service on the
   free plan automatically, building `apps/api/Dockerfile` from the repo
   root.
3. Once the service exists, open its **Environment** tab and set:
   - `DATABASE_URL` — the Neon connection string from step 1
   - `REDIS_URL` — the Upstash connection string from step 2
   - `CORS_ORIGIN` — leave blank for now; you'll set it after step 4 once
     you know the Vercel URL
   - `JWT_SECRET` is auto-generated by the blueprint; leave it as-is, but
     confirm it is at least 32 characters - the API validates this at boot
     and refuses to start otherwise (generate your own with
     `openssl rand -base64 48` if needed)
   - `SWAGGER_ENABLED` - optional; Swagger is off in production unless you
     set this to `true`
   - `LOG_LEVEL` - optional, defaults to `info`. Logs are structured JSON in
     production; every line carries a `requestId` that also appears in each
     response's `meta.requestId` and the `x-request-id` header.
4. Deploy. Render builds the Docker image, runs `prisma migrate deploy`
   against Neon on container start, then boots the API. Health check is
   `/api/v1/health` (liveness - it does not touch PostgreSQL or Redis, so a
   brief dependency blip will not trigger a restart loop). To verify the
   dependencies after deploy, call `/api/v1/health/ready`, which returns 503
   with per-dependency detail while either PostgreSQL or Redis is down.

   If the container exits immediately, check the logs for
   `Invalid environment configuration` - it lists exactly which variables
   are missing or malformed.

5. Note the service URL, e.g. `https://vendoros-api.onrender.com`. The API
   is served under `/api/v1` (Swagger docs at `/api/v1/docs`).

Free-plan note: the service spins down after ~15 minutes idle and takes
~30s to wake on the next request — fine for testing, not for a demo you
need instantly responsive.

To seed the demo tenant (`owner@demo-vendor.ae` / `DemoPassword123!`) after
first deploy, run it once from your machine against the Neon database:

```bash
DATABASE_URL="<neon connection string>" npm run db:seed
```

## 4. Frontend (Vercel)

1. In Vercel, **Add New > Project**, import this repo. Keep the project
   root as the repo root — `vercel.json` handles the monorepo build
   (`npm run build:shared && npm run build --workspace=apps/web`, output
   `apps/web/dist`).
2. Add an environment variable: `VITE_API_BASE_URL` =
   `https://<your-render-service>.onrender.com/api/v1`.
3. Deploy. Note the resulting URL, e.g. `https://vendoros.vercel.app`.

## 5. Close the loop

Go back to Render and set `CORS_ORIGIN` on `vendoros-api` to your Vercel
URL (e.g. `https://vendoros.vercel.app`), then redeploy the API service so
the browser can call it. `CORS_ORIGIN` accepts a comma-separated list, so
you can keep local dev working too, e.g.
`https://vendoros.vercel.app,http://localhost:5173`.

Visit the Vercel URL and sign in with the seeded demo login.

## Alternative: one service instead of four

If juggling four dashboards is more setup than you want, [Railway](https://railway.app)
can host Postgres, Redis, and the API together in one project (still uses
`apps/api/Dockerfile`), leaving only the frontend on Vercel. Railway's free
tier is a monthly credit rather than a permanent free plan, so it's better
for short-lived testing than for something left running indefinitely.
